🎯 Selectores Anidados & Combinadores

Apuntar elementos exactos mediante cadenas de selectores

▶

Los selectores anidados permiten apuntar a un elemento en función de su contexto en el árbol HTML. Combinando etiquetas, clases e IDs con combinadores, se puede seleccionar exactamente el elemento deseado sin añadir clases extra al HTML.

CSS – Los 5 combinadores
/* ── Espacio " " → descendiente (cualquier nivel) ── */
article p          { color: blue; }    /* todo <p> dentro de <article> */
.card .titulo       { color: red; }     /* .titulo dentro de .card */

/* ── > → hijo DIRECTO (solo primer nivel) ── */
ul > li             { color: green; }  /* li hijo directo de ul, no de ul anidado */
.nav > a            { font-weight: bold; }

/* ── + → hermano ADYACENTE (el de inmediato después) ── */
h2 + p              { margin-top: 0; }  /* p que viene justo después de h2 */
input:checked + label{ color: green; }  /* label tras input checked */

/* ── ~ → hermanos GENERALES (todos los siguientes) ── */
h2 ~ p              { font-size: .9rem; } /* todos los p que siguen a h2 */

/* ── , → múltiples selectores ── */
h1, h2, h3          { font-weight: 800; }

/* ── Encadenados: clase + clase, etiqueta + clase ── */
.card.featured      { border: 2px solid gold; } /* elemento con AMBAS clases */
a.btn               { text-decoration: none; }  /* <a> con clase btn */
#header .logo       { width: 120px; }  /* .logo dentro de #header */

/* ── Atributo ── */
input[type="email"] { border-color: blue; }
a[href^="https"]    { color: green; }   /* href que EMPIEZA con https */
img[alt]            { outline: 2px solid red; } /* tiene atributo alt */

/* ── :is() y :where() – selectores modernos ── */
:is(h1, h2, h3)     { line-height: 1.2; }
:where(.card, .box) p{ font-size: .9rem; }  /* igual que :is pero sin especificidad */

/* ── CSS nativo nesting (moderno, sin preprocesador) ── */
.card {
  background: white;
  /* Anidamiento nativo (navegadores modernos 2023+) */
  & .titulo  { font-weight: bold; }
  &:hover    { box-shadow: 0 4px 12px rgba(0,0,0,.1); }
  & > p     { margin-top: 8px; }
}
⚠️ Especificidad — el selector más específico gana
id (100pts) > class / pseudo-clase / atributo (10pts) > etiqueta (1pt). Un selector #header .btn vale 110pts y sobreescribe a .btn (10pts) aunque aparezca después. Cuanto más anidado, más difícil de sobreescribir. Consejo: preferí clases sobre IDs para evitar conflictos de especificidad.

⚡ Pseudo-clases — Eventos CSS

:hover, :focus, :checked, :valid, :nth-child y más

▶

Las pseudo-clases son selectores que se activan en función del estado de un elemento: si el mouse está encima, si tiene el foco, si un formulario es válido. Son la forma en que CSS captura "eventos" sin JavaScript.

CSS – Todas las pseudo-clases clave
/* ── INTERACCIÓN DEL USUARIO ── */
.btn:hover     { background: blue; }     /* mouse encima */
.btn:active    { transform: scale(.96); }  /* durante el click */
a:visited      { color: purple; }         /* link ya visitado */
a:link         { color: blue; }           /* link no visitado */

/* ── FOCO (teclado / click) ── */
input:focus    { border-color: blue; }
:focus-visible { outline: 3px solid blue; } /* solo con teclado */
:focus-within  { background: #f0f8ff; }   /* padre con hijo enfocado */

/* ── FORMULARIOS ── */
input:valid    { border-color: green; }
input:invalid  { border-color: red; }
input:required { border-left: 3px solid orange; }
input:disabled { opacity: .4; cursor: not-allowed; }
input:checked  { accent-color: purple; }     /* checkbox/radio */
input:placeholder-shown { background: #fffde7; } /* mientras muestra placeholder */

/* ── ESTRUCTURALES ── */
li:first-child     { font-weight: bold; }
li:last-child      { border-bottom: none; }
li:nth-child(2)    { color: blue; }        /* el segundo */
li:nth-child(even) { background: #f9f9f9; } /* pares */
li:nth-child(3n+1) { color: red; }         /* 1°, 4°, 7°... */
p:not(.intro)      { font-size: .9rem; }   /* p que NO tiene clase intro */

/* ── :has() — selector "padre" (moderno) ── */
.card:has(img)     { padding-top: 0; }  /* .card que contiene img */
form:has(:invalid) { border-color: red; } /* form con algún campo inválido */

💡 Orden de pseudo-clases en links (LoVeHAte)
Para que los estilos de links funcionen correctamente, deben declararse en este orden: :link → :visited → :hover → :active (mnemónico: LoVeHAte). Si van en otro orden, la especificidad puede pisarlos.

🌊 Transiciones CSS

transition: property · duration · timing · delay

▶

Una transición es un cambio suave y gradual entre dos estados de CSS. En lugar de que el cambio sea instantáneo (como en un :hover normal), la propiedad evoluciona durante un tiempo definido. Las transiciones son reactivas: necesitan un disparador (hover, focus, clase agregada con JS…).

CSS – Anatomía de transition
.elemento {
  /* Shorthand: propiedad | duración | timing | delay */
  transition: background-color .3s ease 0s;

  /* Múltiples propiedades separadas por coma */
  transition:
    transform   .4s cubic-bezier(.34,1.56,.64,1),
    opacity     .3s ease,
    box-shadow  .4s ease;

  /* "all" transiciona TODO — ⚠ cuidado con el rendimiento */
  transition: all .3s ease;
}

/* Propiedades individuales */
.elemento {
  transition-property:        transform, opacity;
  transition-duration:        .4s;
  transition-timing-function: ease-out;
  transition-delay:           .1s;   /* esperar antes de empezar */
}

/* ── Timing functions ── */
transition-timing-function: ease;             /* lento-rápido-lento (default) */
transition-timing-function: linear;          /* velocidad constante */
transition-timing-function: ease-in;         /* empieza lento */
transition-timing-function: ease-out;        /* termina lento */
transition-timing-function: ease-in-out;     /* lento-rápido-lento */
transition-timing-function: cubic-bezier(.34,1.56,.64,1); /* rebote */
transition-timing-function: steps(4);        /* escalonada (pixel art) */
✅ Propiedades que conviene transicionar (GPU-friendly)
transformopacityfilterclip-path
Estas propiedades son aceleradas por GPU y no generan reflow: la animación es suave aunque haya mucho contenido.
🚫 Evitá transicionar estas propiedades
width / heighttop / leftmargin / paddingdisplay
Causan layout reflow: el navegador debe recalcular la posición de todos los elementos afectados. Usá transform: scale() en lugar de cambiar width, y transform: translate() en lugar de top/left.

✨ Animaciones CSS — @keyframes

Secuencias, propiedades, fill-mode y consideraciones finales

▶

Las animaciones CSS permiten definir una secuencia de estados que el elemento recorre automáticamente, sin necesitar interacción del usuario. Se definen con @keyframes (la coreografía) y se aplican con la propiedad animation (la configuración del reproductor).

CSS – @keyframes + animation completo
/* ── 1. Definir la coreografía con @keyframes ── */
@keyframes rebote {
  0%   { transform: translateY(0);    }
  50%  { transform: translateY(-40px); }
  100% { transform: translateY(0);    }
}

/* Equivalente con from/to (solo 2 estados) */
@keyframes fadeIn {
  from { opacity: 0; }
  to   { opacity: 1; }
}

/* ── 2. Aplicar la animación ── */
.elemento {
  /* Shorthand: nombre | duración | timing | delay | iteraciones | dirección | fill-mode */
  animation: rebote 0.8s ease-in-out 0s infinite alternate none;
}

/* Propiedades individuales */
.elemento {
  animation-name:            rebote;
  animation-duration:        0.8s;
  animation-timing-function: ease-in-out;
  animation-delay:           0.2s;
  animation-iteration-count: infinite;  /* o un número: 3 */
  animation-direction:       alternate; /* ver abajo */
  animation-fill-mode:       forwards;  /* ver abajo */
  animation-play-state:      running;   /* running | paused */
}

/* ── animation-direction ── */
animation-direction: normal;           /* from → to (siempre) */
animation-direction: reverse;          /* to → from */
animation-direction: alternate;        /* from→to, to→from, from→to... */
animation-direction: alternate-reverse;/* to→from, from→to... */

/* ── animation-fill-mode — ¿qué estado queda al terminar? ── */
animation-fill-mode: none;             /* vuelve al estado original */
animation-fill-mode: forwards;         /* se queda en el último keyframe */
animation-fill-mode: backwards;        /* aplica from desde el delay */
animation-fill-mode: both;             /* backwards + forwards */

/* ── Múltiples animaciones ── */
.elemento {
  animation: rebote 1s infinite, pulse 2s infinite alternate;
}
none
Vuelve al estado original al terminar. No aplica nada durante el delay.
forwards
Se queda en el estado del último keyframe. Útil para fadeIn que debe quedar visible.
backwards
Aplica el estado del from durante el delay (antes de empezar).
both
Combina forwards + backwards. La opción más completa.

🧠 Restricciones y buenas prácticas

✅ Cuándo usar TRANSICIÓN
Usá transition cuando el cambio depende de una acción del usuario: hover, click, focus. Es declarativa, simple y se "revierte" sola al salir del estado. Ideal para micro-interacciones de UI: botones, cards, inputs, menús.
✅ Cuándo usar ANIMACIÓN
Usá @keyframes cuando el efecto debe ocurrir sin interacción (loading, intro de página, efecto de atención), cuando necesitás más de 2 estados, o cuando la secuencia debe repetirse infinitamente.
⚠️ Rendimiento — regla de oro
Animá solo transform y opacity cuando sea posible. Son aceleradas por GPU y no causan reflow.
transform: translate/scale/rotate opacity filter (con cuidado) width/height top/left/margin
Si necesitás animar posición, usá transform: translate() en lugar de top/left.

♿ Accesibilidad — prefers-reduced-motion

🚨 Muy importante — motion sickness
Algunas personas tienen vértigo o sensibilidad al movimiento (vestibular disorders). Las animaciones excesivas pueden causarles malestar real. El sistema operativo permite configurar "reducir movimiento" y CSS puede detectarlo:
CSS – @media prefers-reduced-motion
/* Desactivar animaciones para usuarios que lo prefieren */
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration:   0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

/* O aplicarlo solo a animaciones no esenciales */
@media (prefers-reduced-motion: no-preference) {
  .hero-elemento {
    animation: fadeInUp 0.6s ease-out both;
  }
}

/* will-change: avisa al navegador que un elemento va a animar */
.animado {
  will-change: transform, opacity;
  /* ⚠ Usalo con moderación — consume memoria de GPU */
  /* Solo en elementos que realmente van a animar */
}
💡 Regla final de oro
Menos es más. Una animación bien elegida mejora la UX; muchas animaciones simultáneas la destruyen. Cada animación debe tener un propósito comunicativo: guiar la atención, dar feedback, explicar un cambio de estado. Si no cumple ninguno de estos roles, eliminala.
