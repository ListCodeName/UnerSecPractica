1. ¿Qué es un Lenguaje Formal?

Estructura matemática y componentes esenciales de cualquier lenguaje de programación

A diferencia del lenguaje humano (lenguaje natural), que está lleno de ambigüedades y dobles sentidos, un lenguaje formal es un conjunto de cadenas de símbolos definido con precisión matemática mediante un conjunto finito de reglas llamadas gramática.

Σ Alfabeto

Conjunto finito y no vacío de símbolos elementales. Por ejemplo: el alfabeto binario {0, 1}, caracteres ASCII o el conjunto Unicode de JavaScript.

w Cadena o Palabra

Secuencia finita de símbolos elegidos de un alfabeto. La longitud de una cadena es |w|. La cadena de longitud cero se llama cadena vacía (ε o λ).

L Lenguaje

Cualquier subconjunto de cadenas formadas sobre un alfabeto (L ⊆ Σ*). Un lenguaje de programación como JavaScript o Python es el conjunto de todos los programas válidos que compilan o ejecutan sin error sintáctico.

2. Simbología, Repetición y Operadores

Metacaracteres universales para definir patrones de repetición, opcionales y alternativas

Haz clic en cada símbolo para explorar su regla de cardinalidad, patrones pedagógicos, casos de uso en lenguajes de programación y cadenas aceptadas vs rechazadas:

Cerradura de Kleene (*)
0 o más repeticiones (0..∞)
*

Indica que el elemento precedente puede aparecer cero veces, una vez o infinitas veces. Por eso, la cadena vacía (ε) siempre forma parte del lenguaje resultante para ese elemento.

Patrón de Ejemplo en Código:
let[ ]*=[ ]*[0-9]+ (Permite 0 o más espacios alrededor del signo '=')
✅ Cadenas Válidas Aceptadas:
"let=50" (0 espacios), "let = 50" (1 espacio), "let = 50" (múltiples espacios)
❌ Cadenas Inválidas (Rechazadas):
"let == 50" (el operador '=' no tiene repetición '*'), "let = abc" (se exigían dígitos)

3. Gramáticas BNF y Derivación Paso a Paso

Cómo se definen las reglas sintácticas y cómo se derivan paso a paso hasta construir código real

Una gramática formal en formato BNF (Backus-Naur Form) define cómo las construcciones complejas se componen de reglas menores. A continuación, observa el conjunto de reglas y cómo se aplica cada una en secuencia para derivar la expresión let suma = 20 + 30;:

📐 Conjunto de Reglas Gramaticales (BNF) Gramática JS Simplificada
(R1) <DeclaracionVar> ::= <DefinidorVar> <NombreVariable> "=" <Expresion> ";"
(R2) <DefinidorVar> ::= "let" | "var" | "const"
(R3) <NombreVariable> ::= <Letra> (<Letra> | <Digito> | "_")*
(R4) <Expresion> ::= <Termino> | <Termino> <OperadorAritmetico> <Termino>
(R5) <OperadorAritmetico> ::= "+" | "-" | "*" | "/"
(R6) <Termino> ::= <Numero> | <NombreVariable>
(R7) <Numero> ::= <Digito>+
(R8) <Letra> ::= "a" | "b" | ... | "z"
(R9) <Digito> ::= "0" | "1" | ... | "9"

5. Tips, Excepciones y Trampas Frecuentes

Preguntas clave y errores habituales al diseñar y validar gramáticas

El analizador léxico (lexer) procesa el código carácter por carácter de izquierda a derecha. Si encuentra un dígito como 7, asume inmediatamente que está leyendo un literal numérico (por ejemplo 750 o 7.25). Si permitiéramos nombres como 7dias, el analizador no sabría si es un número hexadecimal, un error o una variable hasta llegar al final, provocando ambigüedad y requiriendo retroceso (backtracking) ineficiente.
  • Error Léxico: Caracteres extraños no reconocidos en el alfabeto. Ej: let nombre @ 10; (el símbolo @ no existe como operador en esa posición).
  • Error Sintáctico: El orden de los tokens no coincide con la gramática. Ej: let = 10 nombre; (tokens válidos pero en orden incorrecto).
  • Error Semántico: La sintaxis es perfecta, pero no tiene sentido lógico o de tipos. Ej: const x = 10; x = 20; (reasignación a una constante) o llamar a una variable inexistente.
Aunque la palabra class, while o function cumple perfectamente la regla léxica de un identificador (empieza con letra y sigue con letras), las palabras reservadas tienen prioridad máxima en la tabla de símbolos. Por eso, la gramática define una regla de exclusión: <Identificador> ::= <TextoValido> - <PalabrasReservadas>.

Memoriza esta regla de cardinalidad:

* (Kleene): 0 a ∞ (opcional + repetible) + (Positiva): 1 a ∞ (obligatorio al menos uno) ? (Opcional): 0 o 1 (puede estar o no, máximo uno)
